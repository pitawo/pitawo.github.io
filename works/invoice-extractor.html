請求書・注文書の読み取りと一覧化

2026-09 Python JavaScript LLM API（Claude） Content-Security-Policy

課題
請求書・注文書の内容を1枚ずつ見て表に打ち込む作業は、枚数に比例して増え、桁や日付の転記ミスも混ざります。
解決
LLM（文章や画像を理解する AI）で日付・取引先・品目・金額を読み取り、数字が合うかを機械で突き合わせ、合わないものを「要確認」にして、人が確認・修正してから CSV に書き出すツールを作りました。
効果
架空の書類8枚・230項目で照合し、不一致は0件でした（ただし作成も読み取りも同じ AI で n=8＝8枚だけの試験。精度の証明ではありません）。公開デモは、ページを開いたあとの入力・編集内容が外に出ません（確かめボタンを押したときの通信の試行は、ブラウザが遮断します）。その仕組みを誰でも1分で確かめられます。

同じ困りごとを持つ人と、頼めること

請求書や注文書の内容を、1枚ずつ見て表に打ち込んでいる。枚数が増えるほど、転記ミスも増える事務の困りごとです。書類から日付・取引先・金額を読み取り、数字が合うかを機械で突き合わせ、人が確認してから CSV に書き出す流れなら頼めます。実際の書類での精度は未測定なので、まず少量の書類で試す形から始めます。

なぜ作ったか

LLM に書類を読ませる業務ツールは、「便利そう」より先に「大事な書類を外に送っても大丈夫なのか」が問われます。だから機能より先に、安全を自分以外の誰かが確かめられる形にすることを条件にしました。

どう作ったか

公開デモと、手元で動かす版の2つに分けました。

  • 公開デモ（静的ページ）：架空の書類8枚と、その読み取り結果を表示します。確認・修正と CSV 書き出しはブラウザの中だけで動きます。API は呼ばず、キーの入力欄も置いていません。
  • 手元版（Python）：自分の PC で自分のキーで動かします。キーは環境変数からだけ読み、送信先は LLM の API エンドポイント1つだけです。

LLM の「確信度」は使いませんでした。自己申告の確信度は当てにならないので、明細の合計＝小計、小計＋消費税＝合計、数量×単価＝金額を機械で突き合わせ、合わない書類だけを「要確認」にしています。人が見るべき場所を、数字で決めます。

安全性の確かめ方

「保存していません」と書くだけでは証明にならないので、ブラウザ自身が、ページから外へデータを送れないようにする設定（Content-Security-Policy ＝ ブラウザに「このページは外へデータを送ってはいけない」と守らせる設定。connect-src 'none' ほか）をかけました。誰でも1分で確かめられます。

  1. ページのソースで、<head> の先頭付近（文字コード指定の直後）にある CSP を見る。CSP より前に外部の読み込みはありません
  2. 開発者ツールの Network タブで、外部ドメインへの通信が0件であることを見る
  3. キーの入力欄が存在しないことを見る

この方法でできないこと：ページ自体を取得する通信は制御できません。確かめられるのは、開いたあとの入力・編集内容が外に出ないことです。

手元版は、テストで確かめました。テスト用に作った、キーを漏らそうとする疑似の通信相手（キーを本文に返す・ヘッダを全部返す・リダイレクトする）に対して、画面・ログ・出力ファイル・例外・traceback にキーが0件であることを確認しています。

詰まった点と、直したこと

書類の文字が消えた

架空書類を画像に描いたら、文字が白で描かれて、表の見出しの一部しか見えませんでした。描画ライブラリの既定の文字色が白だったためです。

テストが空振りしていた

「リダイレクト先にキーが送られない」というテストが、実装を壊しても通りました。偽サーバが POST しか記録しておらず、リダイレクトを追うと GET になって記録されなかったためです。実装をわざと壊してテストが落ちるかを確かめて、初めて気づきました。

ブラウザテストの待機が動かなかった

CSP が文字列の評価を禁じているため、テストツールの待機処理が拒否されました。設定が実際に効いていることの証拠にもなりました。

ここから学んだこと

「0件」を確かめるテストは、検出できることを先に確かめないと意味がありません。今回は、わざと漏らしたキーを見つけられること、CSP を外した複製では外部通信が実際に出ることを先に確認してから、実物の0件を確認しました。

公開について

デモの読み取り結果は、API を呼んで作ったものではありません。同梱のプロンプトと同じ指示で、Claude Code が書類の画像を見て書いたものです。

正答率は、書類を作ったときの正解との照合（230項目で不一致0）だけです。実際の API・実際のスキャン書類での正答率と、1枚あたりのコストは未測定です。書類はすべて架空で、実在の社名・人名・住所・登録番号は使っていません。
