動画講座配信プラットフォーム

2026-08 Next.js / Drizzle ORM / Better Auth Claude Code

なぜ作ったか

以前作った秘書アプリは、ブラウザとローカルのサーバーだけで完結する個人用ツールでした。次は、ログイン・データベース・本番デプロイまで含めて、誰かがブラウザから触れる形のアプリを一人で作りきることを目標にしました。

題材には、自分が G検定の学習でまとめていた「AI の歴史」を選びました。人工知能の定義から、ブームと冬の時代が繰り返されてきた流れまでを、レッスン単位で並べて見返せる形にしています。

どう作ったか

構成は Next.js（フロントエンドと API）・Drizzle ORM・Turso（本番データベース）・Better Auth（メール＋パスワードと Google ログイン）・Vercel Blob（サムネイル画像）です。開発中はローカルの SQLite に向けて作り、公開の直前に接続先を本番のデータベースへ切り替えました。

Claude Code に要件と技術構成を渡して実装させ、動かして気づいた点を戻す進め方は前作と同じです。今回は自動テストも合わせて書かせ、コードを直すたびにテストと型チェックを通してから次に進めました。

詰まった点と、直したこと

このアプリで一番危なかったのは、機能の作り込みではなく見えている情報と実際の動きがずれる問題でした。

設定を読み込む順番で、書き込み先がずれていた

データを流し込むスクリプトが「本番データベースに書き込みました」とログに出すのに、実際にはローカルのファイルに書き込まれている状態が起きていました。原因は、設定を読み込む処理より先に、データベースへの接続処理が実行されていたことです。ログが参照している場所と、接続が実際に見ている場所がずれていました。

設定を読み込む処理を一番最初に置き直し、接続先は「たぶんこの値のはず」ではなく、実際に接続したモジュール自身に報告させる形に変えました。

レッスンを切り替えても「完了」ボタンの状態が前のまま残った

動画とタイトルは切り替わるのに、完了ボタンだけ前のレッスンの状態を表示し続ける不具合がありました。原因は、レッスンを切り替えても表示コンポーネント自体は再利用され続け、内部で持っている状態が初期化されないことでした。

レッスンが切り替わるたびにコンポーネントごと作り直す指定を加えて直しました。

新規登録に、管理者権限を混ぜ込める穴があった

新規登録の API に渡すデータへ、本来は使わないはずの「権限」の項目を混ぜて送ると、誰でも管理者として登録できてしまう状態でした。動作確認では気づきにくく、リクエストの中身まで見て初めて分かる種類の問題でした。

権限の項目は登録時に外部から書き込めないよう固定し、内部処理だけが変更できる形にしました。

ここから学んだこと

「動いて見える」と「本当にその通り動いている」は別でした。ログに出ている情報や画面の表示は、実際の状態とずれることがあります。前作で学んだ「壊れるところを考えるのは使う側の仕事」に加えて、今回は表示されている情報をそのまま信じないという点も学びました。

公開について

本番で公開中です。ログインしなくても講座一覧とレッスンの内容は見られ、Google ログインで受講と進捗の記録ができます。

現状、レッスン動画は10本中1本のみ公開済みで、残り9本は制作中です。音声つきの解説動画は、資料を読み込ませると音声解説付きの動画にしてくれる NotebookLM で作っています。動画ができ次第、管理画面から順に差し替えていきます。
