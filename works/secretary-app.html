自分専用の秘書アプリ

2026-08 Node.js / HTML / CSS / JavaScript Claude Code

なぜ作ったか

既存のタスク管理アプリはどれも機能が多く、自分が使う3つ（メモ／タスク／週次の振り返り）以外の要素が視界に入ります。使う機能だけが1画面に載っている状態が欲しくて、既製品を探すのをやめて作ることにしました。

「AI で作れるらしい」を試すのが目的ではなく、毎日開くものを自分の形に合わせるための制作です。

できること

  • メモ — 追加・編集・削除。編集すると更新日時が付く
  • タスク — 追加・完了・未完了に戻す・編集・削除。完了日時を保持
  • 週次の振り返り — 週を選んでコメントを記録
  • ダッシュボード — 各件数と、最新の振り返りを表示

どう作ったか

Claude Code に要件を渡して実装させ、動かして気づいた点を戻す、を繰り返しました。コードの書き方は指示していません。指示したのは「何が欲しいか」と「動かして違和感があった点」だけです。

技術的な選択として、外部ライブラリを1つも使わない方針を取りました。npm install が要らないので、環境を作り直しても node server.js だけで動きます。

詰まった点と、直したこと

このアプリで一番時間を使ったのは、機能追加ではなくデータが消える問題でした。

保存が競合してデータが消えた

「ファイルを読む → 書き換える → 保存する」の途中に別のリクエストが割り込むと、あとから保存したほうで上書きされて、先に追加したデータが消えていました。動作確認では気づきにくく、素早く連続で操作したときだけ起きます。

処理を1件ずつ順番に実行するキューを入れて解決しました。前の処理が失敗しても次が止まらないようにしてあります。

保存の途中で落ちるとファイルが壊れる

書き込み中にプロセスが落ちると、JSON が途中まで書かれた壊れた状態で残ります。次の起動時に読めません。

一時ファイルに書き切ってから本体と置き換える方式に変えました。置き換えは一瞬で終わるので、途中の状態が残りません。

壊れたファイルを読むと起動しない

上の対策をしても、手で編集して壊す可能性は残ります。読み込み時に形を検査して、想定と違えば空の状態で起動を続けるようにしました。初回起動（ファイルが無い状態）も同じ経路で扱えます。

公開について

その場で触れるデモを公開しています。保存先をブラウザの中（localStorage）に置き換えたもので、入力した内容はどこにも送信されません。別の端末には引き継がれません。

サーバー版と同じコードで動かしています。起動時に一度だけ保存先の有無を調べ、無ければブラウザ内に切り替える形にしたので、node server.js で立ち上げれば従来どおりファイルに保存されます。保存先が違うだけで、入力チェックも並び順もエラーメッセージも揃えてあります。

ここから学んだこと

「動く」と「壊れない」は別でした。最初に動いた時点では3つとも起きておらず、使い始めてから順番に出てきたものです。AI に実装させると動くところまでは速いのですが、どこで壊れるかを考えるのは使う側の仕事だと分かりました。
