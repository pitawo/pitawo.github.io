フォーム回答のスコアリングと結果配信

2026-08 Google Apps Script JavaScript Google Workspace

なぜ作ったか

依頼を受けて作ったツールです。診断形式のアンケートに答えてもらい、その結果に応じて別々の案内を届けたい、という要件でした。

手作業でやると、回答を1件ずつ見て、点数を数えて、該当する文面を選んで、コピーして送ることになります。回答が増えるほど時間がかかり、しかも数え間違いが混ざります。回答が届いた時点で、正しい相手に正しい内容が届いている状態にしたかったので作りました。

もう1つ、送ったメールは埋もれます。「あのとき何点だったか」をあとから確認できる場所が要ると考え、結果を再表示できるページも一緒に作りました。

どう作ったか

Google Apps Script で組みました。フォーム送信をきっかけに処理が走ります。

フォーム送信 → スプレッドシートに記録 → Yes/No の設問を集計してスコアを出す → スコアからタイプを判定（A / B / C） → メタ列に書き込む → タイプ別の内容でメールを送信 → 結果ページでいつでも再表示

結果ページには入り口を2つ用意しました。メールに載せたトークン付きURLと、メールアドレスを入力する方法です。URLを失くしても自分で辿り着けます。

設問・判定の区切り・文面はすべて設定として上に出してあります。中身を変えるのにコードを触る必要はありません。

詰まった点と、直したこと

作った直後は動いていました。壊れたのは運用に入ってからです。

同じ人が送信したのに、結果ページで見つからない

メールアドレスで検索する経路が、ときどき失敗しました。原因は Gmail の仕様でした。

  • taro+form@gmail.com と taro@gmail.com は同じ受信箱に届く
  • ta.ro@gmail.com も同じ

フォームに入れたアドレスと、結果ページに入力したアドレスが、本人にとっては同じでも文字列としては違っていました。gmail 系のドメインでは + 以降を削除し、ドットを無視してから比較するようにしました。

この分岐は、設計している段階では思いつきませんでした。実際に「見つかりません」と言われて初めて気づいたところです。

設問の見出しが一致しない

スコアの集計は、シートの見出しと設定した設問文を突き合わせて行います。ところが全角スペースが1つ混ざっているだけで一致しなくなります。フォームを編集したときに紛れ込みます。

全角→半角、連続スペースの圧縮、前後の空白削除を通してから比較するようにしました。あわせて、一致しない見出しがあればどの設問で失敗したかを名指しで出すようにしています。「動きません」だけでは直せないためです。

メールの列が、いつも同じ場所にない

フォームの設定によって、メールアドレスがどの列に入るかが変わります。列を固定すると、設定が変わった瞬間に動かなくなります。

2段階で探すようにしました。まずヘッダ名から探し（mail / メール / e-mail を含む列）、見つからなければデータそのものを見て推定します（先頭30行を調べ、@ が3回以上出現する列を候補に加える）。

トリガーが止まっていた期間の回答が、空のまま残る

権限の再承認などでトリガーが止まると、その間の回答にはスコアもタイプも書かれません。気づいたときには数十件たまっています。

既存の全行を再計算する関数を用意しました。手動で実行すると、空いている行を埋め直します。すでに発行済みのトークンはそのまま残すので、配ったURLは生きたままになります。

ここから学んだこと

「入力は正しい形で来る」という前提が、いちばん最初に壊れました。メールアドレスの表記ゆれも、見出しの全角スペースも、列の位置も、すべて「そうなっているはず」と思っていたところでした。

そして直し方が共通していました。厳密に一致させようとするのではなく、揺れを吸収してから比較する。正規化を挟むだけで、後から起きるはずだった問題がまとめて消えました。

もう1つは、復旧する手段を最初から持っておくことです。自動化は止まります。止まったこと自体は避けられません。止まったあとに手作業へ戻らずに済むかどうかで、運用の負担がまったく変わります。再計算の関数を書いておいたおかげで、止まっていた期間の後始末が実行1回で終わりました。

公開について

依頼元から実績として掲載する許可を得たうえで、設問・文面・URL・配色をサンプルに差し替えて公開しています。処理のロジックは、実際に運用していたものと同じです。

デモは結果ページの表示を再現したものです。GAS のウェブアプリは Google アカウント上にデプロイして動くため、そのままでは触れる形で置けません。表示されている内容は、スクリプトが生成するものと同じ構造にしてあります。
