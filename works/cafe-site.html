カフェの注文サイト

2026-08 React / Vite React Router / Vitest

デモを触る GitHub で見る

なぜ作ったか

買い物のサイトは、見た目を作るところまでは早いです。難しいのはその先で、カートの中身を持ち回り、金額を計算し、決済画面まで途切れずにつなぐところに手間がかかります。

作りかけで止まっているものが手元にあったので、注文から決済まで一本の流れとして通せる状態にしました。

どう作ったか

React と Vite。画面は6つ（トップ・メニュー・カート・決済・完了・サインイン）で、React Router で切り替えます。表示は日本語、金額は円に統一しました。触りに来た人がそのまま読めるようにするためです。

カートの状態は Context にまとめ、金額の計算もそこに置きました。

項目計算
小計単価 × 数量の合計
消費税小計の 10%
配送料店頭受け取りは無料、配達は ¥300

受け取り方法を切り替えると合計が変わります。ドリンクには S / M / L のサイズも足しました。M は +¥50、L は +¥100 で、選んだサイズの差額はカート・小計・合計まで一貫して反映します。

決済画面は省略しませんでした。カード番号・名義・有効期限・セキュリティコードの入力欄を持ち、支払いボタンには金額を出します。押すと待ち時間を挟んで完了画面へ進み、DEMO-年月日-4桁 の受付番号を出します。

ただしカード情報はデモ用の値を入れて読み取り専用にしました。触りに来た人が実在のカード番号を打ち込む余地をなくすためです。入力された内容はブラウザの外に出ません。

画像を用意した

商品6品・店の外観・ロゴを生成して同梱しました。以前は外部のプレースホルダ画像を6回読んでいましたが、これでページから外部への通信がゼロになりました。

用途中身容量
商品(写真) 6品俯瞰・明るい木目・斜めから入る自然光で揃えた各 20KB 前後
店の外観トップの背景。文字が読めるよう暗い膜を重ねる75KB
ロゴヘッダー用13KB

その後、スイーツ・フードを6品足してメニューを12品にしました。追加分は写真を用意していないので、線画の SVG イラストで揃えています。

ロゴは2回作り直しました。

1回目は細い線のカップの絵で、ヘッダーの 28px では潰れて判別できませんでした。余白を切り落として線を太らせましたが、今度は「カップの絵がある」だけで店を識別するマークになっていないという問題が残りました。

2回目は円形のエンブレム型にしました。二重の円枠の中に、コーヒーの枝を持つ人物の横顔。髪が湯気のように渦を巻いてカップの形になっています。線ではなく塊で描かせたので、縮めても形が残ります。

サイズは 28 / 32 / 36px に実際に縮めて見比べ、枝と輪郭が読める 36px にしました。小さく置く絵は、小さくしてから確かめないと分かりません。

詰まった点と、直したこと

このサイトで一番まずかったのは、入力されたパスワードを記録していたことでした。

パスワードがそのまま記録に残っていた

認証の処理に、入力されたメールアドレスとパスワードを開発者向けの記録に出す1行が残っていました。動作を確かめるために書いたものが、そのまま公開の手前まで来ていたわけです。

削除したうえで、パスワードの入力欄そのものを廃止しました。このデモには認証サーバーが無く、パスワードを照合する相手がいません。持たないほうが正しい。サインインはメールアドレスだけ、しかも入力は任意にしました。

読み込み直すとカートが消える

カートの中身を画面の状態としてだけ持っていたので、ページを再読み込みすると空に戻りました。商品を選んでいる途中で戻るボタンを押しただけで消えます。

ブラウザの中に保存するようにしました。保存できない環境では、その回のあいだだけ保持する形にしてあります。

空のカートで注文できた

カートが空でも決済画面に進めて、合計 ¥0 のまま注文が完了しました。空のときは決済に進ませず、メニューへ案内するようにしました。

テストが通っていたのに、何も確かめていなかった

購入の流れを確かめるテストを10項目書いて、全部通りました。その後で、実装をわざと壊してみました。

カード欄の読み取り専用を外したら、カードのテストだけが落ちました。消費税の率を 10% から 8% に変えたら、金額を見ている3件が落ちました。

通ったことと、確かめられていることは違います。壊して初めて、テストが本当にその場所を見ているか分かりました。

ここから学んだこと

動作を確かめるために書いたものが、そのまま公開まで残ります。パスワードを記録に出す1行は、書いた時点では確認のためのものでした。消す前提のものほど、消し忘れても誰も困らないので残り続けます。

もう1つは、「危ないから消す」と「見せたいから残す」は両立できるという点です。決済画面は、このサイトで一番見せたい部分でした。最初はカード欄ごと削ろうとしましたが、それでは見せたいものが無くなります。入力できなくすれば、画面は残せます。

公開について

静的なサイトなので、開けばすぐ動きます。サインインは入力なしで通れます。カートの中身はブラウザの中にだけ残ります。

配信はサブディレクトリなので、ビルド時に基準パスを渡し、画面遷移の基準もそれに合わせています。加えて、/menu のような途中の画面を直接開いてもアプリが引き受けられるよう、404.html で元のパスを sessionStorage に保存してから入口へリダイレクトし、入口側でその値を読んで元の画面に戻すようにしました。
