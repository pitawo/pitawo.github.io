これはデモです。 Google Apps Script が生成する結果ページの表示を再現したものです。実際のツールはフォーム送信をきっかけに動き、スプレッドシートの回答からスコアを算出して、この画面とメールを出し分けます。GAS のウェブアプリは Google アカウント上にデプロイして動くため、そのままの形では触れる状態に置けません。
表示されている点数・タイプ・本文の構造は、スクリプトが実際に出力するものと同じです。 ソースは GitHub にあります。

すぐに着手できる状態です

手順が決まっていて、データも扱える形で残っている。この2つが揃っているので、自動化の効果がそのまま出ます。

この状態で先に決めておくとよいこと

  • どの作業から自動化するか（頻度 × 1回あたりの時間で選ぶ）
  • 失敗したときに手作業へ戻せる導線を残すか
  • 作った後、誰が直せる状態にしておくか

作ること自体より、運用が続く形にすることのほうが難しくなります。

まず現状を測るところから

いきなりツールを入れるより、どの作業にどれだけ時間がかかっているかを把握するほうが先です。ここを飛ばすと、効果の薄いところを自動化してしまいます。

最初の一歩

  • 1週間、作業と所要時間を記録する
  • 「毎回同じ」と「毎回違う」を分ける
  • 同じもののうち、最も回数が多いものを1つ選ぶ

測ってから決めるほうが、結局は近道になります。

この画面が出るまでに何が起きているか

フォーム送信
   ↓  onFormSubmit（インストール型トリガー）
スプレッドシートに回答が記録される
   ↓
Yes/No 設問を集計してスコアを算出（0〜5点）
   ↓
スコアからタイプを判定（A / B / C）
   ↓
メタ列に書き込み（Score / Type / Token / ResultURL）
   ↓
タイプ別の内容でメールを送信
   ↓
この結果ページ（固定URL）でいつでも再表示

結果ページの入り口は2つあります。メールに載せたトークン付きURLと、メールアドレスの入力。 後者は +エイリアス とドット表記を正規化してから照合するため、 taro+form@gmail.com で送信して taro@gmail.com で検索しても同じ結果に辿り着きます。
